# @jaypie/testkit 1.2.65

## Bug Fixes

- **`toThrowError` no longer shadows vitest's built-in matcher**: The exported matcher was `async` and accepted no `expected` argument. Because `expect(fn).toThrowError(...)` is a synchronous call site, vitest never awaited it: a failing assertion surfaced as an unhandled rejection while the test reported as passing, and `toThrowError(SomeError)` asserted only that something threw. The matcher is removed; vitest's built-in already covers sync throws, async rejections, error classes, messages, and expressions. The Jaypie-specific matchers (`toThrowJaypieError` and siblings) are unchanged.

## Migration

No call-site changes are required. Suites that installed the matchers may find assertions that were silently passing now fail, which is the intended behavior.
