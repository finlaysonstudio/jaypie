## Changes

- A file or image part with `data: ""` throws `BadRequestError` (#626). Presence is now `data != null`, so an empty string no longer falls through to S3 or the local filesystem.
- `loadLocalFile` throws `BadRequestError` on a missing file instead of a raw ENOENT.
- A caller `BadRequestError` from `@jaypie/errors` is terminal in a fallback chain: no next model and no linger pass. Provider 400s are normalized to `LlmUnrecoverableError` and still fall over.

## Upgrade

- A 0-byte upload sent as `data: buffer.toString("base64")` now rejects with `BadRequestError`. Check for an empty buffer before calling to handle it differently.
