## Changes

- Tables are always inline. `[tbl-0.md](tbl-0.md)` placeholders, which Mistral returns whenever `table_format` is sent, are replaced with the table content in the syntax `tables` selects
- Every image is described. Requests carry a default `bbox_annotation_format` (`{ image_type, description }`, with signature, seal, and stamp in the enum). The description becomes the image's alt text, `![Notary seal](img-2.jpeg)`, and `LlmOcrImage` gains `annotation`, `description`, and `type`
- Typed blocks are rendered. When OCR 4 returns `blocks`, page markdown is rebuilt from them, so a signature reads `[Signature: Jane Q Doe]` rather than a bare name. Header and footer blocks are skipped when extracted to their own fields
- `PAGE_COST_ANNOTATED` prices annotated pages ($5 per 1,000 on `mistral-ocr-4-1`); `usage.cost` uses it unless annotation is disabled
- `providerOptions.bbox_annotation_format` replaces the default schema, and `null` disables annotation
- `Llm.ocr` accepts `instructions` and `format` (Natural Schema, JSON Schema, or Zod) and returns the answer on `content`. Mistral answers in the same call through `document_annotation_prompt` and `document_annotation_format`; beyond its 8-page annotation limit, and on emulated engines, one text-only `operate()` over the markdown answers instead. LlamaParse throws `NotImplementedError` before submitting, so a chain fails over
- Mistral `document_annotation` is parsed from its JSON string before it lands on `annotations`
- Fallback chains (`operate`, `ocr`, `question`) fail over on any error with no retry or wait, the last entry included. When the chain is spent, the primary runs once more with its full retry policy; if that fails, the call throws. Previously transient errors retried up to six times on each entry and the last entry kept its rate-limit wait
- An explicit `retry` option on a chained call applies to the linger pass only
- `LlmRetryOptions` gains `transient: false`, which disables transient-error retries
- A caller abort (`LlmAbortError`) no longer falls over to the next entry
- The Bedrock client is built with `maxAttempts: 1`, so SDK retries no longer stack under `RetryExecutor`
