## Changes

- `MistralProvider`, `MistralAdapter`, and a fetch-based `MistralClient`
  (OpenAI-compatible Chat Completions at `https://api.mistral.ai/v1`). No new
  dependencies — Mistral has no Responses API, so the adapter follows the
  Fireworks/OpenRouter Chat Completions pattern rather than extending
  `OpenAiAdapter`.
- Catalog: a nested `MODEL.MISTRAL` subtree — `LARGE` (`mistral-large-2512`,
  the provider default), `MEDIUM` (`mistral-medium-3-5`), `SMALL`
  (`mistral-small-2603`), and `OCR` (`mistral-ocr-4-0`). `COST` prices the
  three chat models; OCR bills per page and is deliberately unpriced.
  `MODEL.MISTRAL.LARGE` is held out of the live capability matrix, so the
  Mistral default ships without live coverage and Medium 3.5 and Small 4 carry
  the shard.
- Routing: a `mistral:` prefix, the `mistral` provider name, and seven match
  words (`mistral`, `ministral`, `codestral`, `devstral`, `magistral`,
  `pixtral`, `voxtral`) — most Mistral family names do not contain the
  substring "mistral". The match loop runs after Bedrock and after the `/`
  rule, so `mistral.mistral-*` still resolves to `bedrock` and `mistralai/*`
  still resolves to `openrouter`.
- **File input is carried, not discarded.** Mistral's `document_url` content
  part accepts the base64 `data:` URI the upload pipeline already produces, so
  PDFs work without a Files API round-trip. Images use `image_url`.
- Structured output uses native `response_format: json_schema` with
  `strict: true`, and **combines with tools natively** — no preemptive
  emulation. A runtime fallback to the `structured_output` tool remains for
  models that reject the pair. Large 3 and Small 4 answer cleanly. **Mistral
  Medium 3.5 does not**: after a tool result it degenerates into restating its
  answer, and lands on any of three outcomes from the same build — a 502
  `Bad Function Call` (the repeated objects emitted as a tool *name*), a warn
  (the corrective `structured_output` turn recovers a valid object), or a clean
  object — and, most often, a tool-call loop: instead of answering from the
  tool result it calls the tool again, turn after turn, until the budget is
  exhausted. No single expectation is stable, so that one matrix cell is
  skipped; the model's other six cells still run. Note the conversion below
  does **not** rescue this case — it only runs when a format request completes
  as prose, and here the loop exits through the tool-call branch.
- **New fresh-context conversion for format contract enforcement.** When a
  `format` request completes as prose, adapters can now opt into
  `supportsStructuredOutputConversion` instead of (before) the existing
  corrective turn. Rather than re-asking inside the same conversation, the loop
  makes a single context-free call that does nothing but transcribe the prose
  into the schema — no history, no tools, no system prompt.
  This is both more reliable and more faithful. Re-asking in context lets a
  model that has already degenerated keep degenerating, and lets it re-derive
  values it never produced: in one observed case a tool rolled 5,2,4,3,5
  totalling 19 and the corrective turn answered 4,1,6,2,5 totalling 18. The
  conversion call can only transcribe what it is handed — 5 for 5 identical and
  correct on the same input, ~500ms and 26 output tokens. Enabled for Mistral;
  other adapters keep the corrective turn, which remains the fallback when
  conversion yields nothing. Usage from the extra call is tallied.
- **Non-streaming output is now capped** (32,768 model max, 16,384
  non-streaming, via `resolveMaxOutputTokens`). Mistral publishes no low output
  ceiling, but an uncapped completion is a real latency hazard: the degenerate
  Medium 3.5 path above ran a single matrix cell for **7m57s** in CI against
  under 1.5s for every other cell. Override with
  `providerOptions: { max_tokens }`.
- Reasoning effort maps to `reasoning_effort`, gated by model. Mistral Large 3
  does not reason; Medium 3.5 and Small 4 accept only `none` and `high`, so the
  five-point neutral scale collapses to a binary (`lowest` → `none`, everything
  else → `high`). A model that rejects the field at runtime is cached and the
  request transparently retried without it.
- Prompt caching via `prompt_cache_key`; cached tokens surface as
  `usage.cacheRead` and bill at 10% of input.
- `MistralProvider.ocr()` wraps `POST /v1/ocr`, returning joined page markdown
  plus the raw response. It sits outside the `LlmProvider` interface and is not
  reachable through the `Llm` facade.
- Testkit mocks `MistralProvider`; CI gains a `mistral` matrix shard using
  `CICD_MISTRAL_API_KEY`.

### Fireworks catalog refresh

- `MODEL.FIREWORKS.KIMI` repoints from `kimi-k2p7-code` to `kimi-k3`. Note the
  cost jump: $0.95/$4.00 becomes **$3.00/$15.00** per million. The superseded
  id keeps its `COST` entry so historic usage stays replayable.
- New `MODEL.FIREWORKS.INKLING` (`accounts/fireworks/models/inkling`) —
  $1.00/$4.05, 1M context, vision and tools.
- New `MODEL.FIREWORKS.NEMOTRON`
  (`accounts/fireworks/models/nemotron-3-ultra-nvfp4`) — $0.60/$2.40, already
  priced from its earlier stint in the catalog. It was retired 2026-07-21 for
  nondeterministic structured output; `structured` now passes 6 for 6 on
  resample, so it is pinned `ok` on evidence. A regression should pin
  `structured: "warn"` rather than remove the model again.

### Divergences from the other OpenAI-compatible providers

Both verified against the live API on 2026-08-01:

- **Unknown request fields are rejected with HTTP 422 `extra_forbidden`.**
  Mistral has no `user` field, and names the seed `random_seed`. The adapter
  never sends `user`, and `providerOptions` is not a free-form passthrough on
  this provider — values must belong to Mistral's own request schema.
- **The error `message` is polymorphic** — a plain string on model-level
  errors, an object (`{ detail: [{ loc, msg }] }`) on schema validation. The
  client renders the object form as `body.field: message` rather than
  `[object Object]`, preserving the field names that make a 422 actionable.
- Reasoning responses return `content` as an **array of chunks**
  (`thinking` then `text`) rather than a string. The adapter splits them, so
  `content` stays the answer and the thinking text lands on `reasoning`.
- The rate-limit error `type` is `rate_limited`, not the `rate_limit_error`
  named in Mistral's published error glossary.

## Testing

- 93 new unit tests across `MistralAdapter`, `MistralClient`, and
  `MistralProvider`, plus a Mistral block in `determineModelProvider` with
  regression assertions that Bedrock- and OpenRouter-hosted Mistral ids keep
  their existing providers.
- Env-gated live hot tests at
  `src/providers/mistral/__tests__/client.hot.spec.ts`, including an assertion
  that unknown fields still 422 — the adapter depends on that staying true.
- All seven live capability cells (plain, tools, structured, both, pdf, image,
  temperature) verified against the real API for all three chat models. The
  only `MATRIX_EXPECT` override is `mistral-medium-3-5` `both: "skip"`,
  described above. With it skipped and output capped, the whole Mistral shard
  runs in about 10 seconds.
- Mistral's rate limits are tight and it returns no `Retry-After`, so a full
  `APP_GROUP=mistral` run can surface spurious `Rate limit exceeded` cells;
  re-run the affected models individually with `APP_MODELS` to confirm before
  treating one as a capability failure.
