## Changes

- `MistralProvider`, `MistralAdapter`, and a fetch-based `MistralClient`
  (OpenAI-compatible Chat Completions at `https://api.mistral.ai/v1`). No new
  dependencies — Mistral has no Responses API, so the adapter follows the
  Fireworks/OpenRouter Chat Completions pattern rather than extending
  `OpenAiAdapter`.
- Catalog: a nested `MODEL.MISTRAL` subtree — `LARGE` (`mistral-large-latest`,
  the provider default), `SMALL` (`mistral-small-latest`), and `OCR`
  (`mistral-ocr-4-0`). `COST` prices the chat models by dated id
  (`mistral-large-2512`, `mistral-small-2603`) rather than under the alias, so
  `COST[MODEL.MISTRAL.LARGE]` misses by design — resolve the alias to the id
  the API echoes and price that. OCR bills per page and is deliberately
  unpriced. Both chat models carry the live capability matrix and pass every
  cell.
- **`mistral-medium-3-5` is deliberately not cataloged.** It could not combine
  tools with structured output reliably — after a tool result it re-calls the
  tool instead of answering, and the same build produced a clean pass, a
  conversion warn, a 502 `Bad Function Call` with concatenated JSON emitted as
  the tool *name*, and a request that hung to a headers timeout. Structured
  output with tools is a baseline expectation of `operate()`, so the model is
  not offered. It stays **priced but unexported**: `mistral-medium-3-5` keeps
  its `COST` entry, since a caller can still pass the id and existing usage
  records reference it. Pricing a model is not endorsing it — `COST` answers
  what something cost, not what to use.
- Routing: a `mistral:` prefix, the `mistral` provider name, and seven match
  words (`mistral`, `ministral`, `codestral`, `devstral`, `magistral`,
  `pixtral`, `voxtral`) — most Mistral family names do not contain the
  substring "mistral". The match loop runs after Bedrock and after the `/`
  rule, so `mistral.mistral-*` still resolves to `bedrock` and `mistralai/*`
  still resolves to `openrouter`.
- **File input is carried, not discarded.** Mistral's `document_url` content
  part accepts the base64 `data:` URI the upload pipeline already produces, so
  PDFs work without a Files API round-trip. Images use `image_url`.
- Structured output uses native `response_format: json_schema` with
  `strict: true`, and **combines with tools natively** — no preemptive
  emulation. A runtime fallback to the `structured_output` tool remains for
  models that reject the pair. Both cataloged models answer cleanly.
- **New fresh-context conversion for format contract enforcement.** When a
  `format` request completes as prose, adapters can now opt into
  `supportsStructuredOutputConversion` instead of (before) the existing
  corrective turn. Rather than re-asking inside the same conversation, the loop
  makes a single context-free call that does nothing but transcribe the prose
  into the schema — no history, no tools, no system prompt.
  This is both more reliable and more faithful. Re-asking in context lets a
  model that has already degenerated keep degenerating, and lets it re-derive
  values it never produced: in one observed case a tool rolled 5,2,4,3,5
  totalling 19 and the corrective turn answered 4,1,6,2,5 totalling 18. The
  conversion call can only transcribe what it is handed — 5 for 5 identical and
  correct on the same input, ~500ms and 26 output tokens. Enabled for Mistral;
  other adapters keep the corrective turn, which remains the fallback when
  conversion yields nothing. Usage from the extra call is tallied.
- **Non-streaming output is now capped** (32,768 model max, 16,384
  non-streaming, via `resolveMaxOutputTokens`). Mistral publishes no low output
  ceiling, but an uncapped completion is a real latency hazard: a degenerate
  path ran a single matrix cell for **7m57s** in CI against under 1.5s for
  every other cell. Override with `providerOptions: { max_tokens }`.
- Reasoning effort maps to `reasoning_effort`, gated by model. Mistral Large
  does not reason; the reasoning models accept only `none` and `high`, so the
  five-point neutral scale collapses to a binary (`lowest` → `none`, everything
  else → `high`). A model that rejects the field at runtime is cached and the
  request transparently retried without it.
- Prompt caching via `prompt_cache_key`; cached tokens surface as
  `usage.cacheRead` and bill at 10% of input.
- `MistralProvider.ocr()` wraps `POST /v1/ocr`, returning joined page markdown
  plus the raw response. It sits outside the `LlmProvider` interface and is not
  reachable through the `Llm` facade — construct `MistralProvider` directly. The
  `OcrRequest`, `MistralOcrResponse`, and `MistralOcrPage` types are exported
  from the package root so callers can name them.
- Testkit mocks `MistralProvider`; CI gains a `mistral` matrix shard using
  `CICD_MISTRAL_API_KEY`.

### xAI: Grok 4.5, and a literal id in place of the alias

- `MODEL.GROK` repoints from `grok-latest` to **`grok-4.5`**, priced
  $2.00/$6.00 with $0.30 cached reads (the sub-200K tier; xAI doubles every
  figure at or above 200K input, which `COST` excludes as a long-prompt
  surcharge). `PROVIDER.XAI.DEFAULT` follows.
- **`COST` no longer prices any `-latest` alias.** An alias has no stable
  price: the provider can repoint it at any time, and an entry under the alias
  would keep returning the old rate with nothing to signal the move. Resolve
  the alias to the id the API echoes on the response and price that.
  `grok-latest` resolved to `grok-4.3` on 2026-08-02; had it moved to 4.5
  unnoticed, output cost would have been understated by 140%.
  A constants test now asserts that every `-latest` id in `MODEL.*` is absent
  from `COST`, and the "prices every first-class model" invariant excludes
  aliases explicitly rather than by omission.
- The rest of the xAI catalog is priced by literal id: `grok-4.3`,
  `grok-4.20-0309-reasoning`, `grok-4.20-0309-non-reasoning`,
  `grok-4.20-multi-agent-0309` (all $1.25/$2.50, $0.20 cached), and
  `grok-build-0.1` ($1.00/$2.00, $0.20 cached). Ids verified against
  `GET /v1/models`. Release order is 4.1 < 4.20 < 4.3 < 4.5 — `4.20` is 4.2.0
  with the patch segment kept, not minor version twenty, so it looks newer than
  4.3 under a semver reading and is not. The retired
  `grok-4-1-fast-*` pair keeps its entries. `grok-imagine-*` are image and
  video models priced per asset, which `LlmModelCost` cannot express, so they
  are deliberately absent.
- `pdf` is pinned `skip` for Grok 4.5. It read the fixture document in 2 of 9
  live samples; the other seven narrated "I'll extract the text from the PDF
  using the available tools" in a cell that configures no tools, returning none
  of the document's text. Grok 4.3 passed the same cell 2 for 2, so this is a
  regression in 4.5. Every other Grok 4.5 cell passes, `both` included.

### Fireworks catalog refresh

- `MODEL.FIREWORKS.KIMI` repoints from `kimi-k2p7-code` to `kimi-k3`. Note the
  cost jump: $0.95/$4.00 becomes **$3.00/$15.00** per million. The superseded
  id keeps its `COST` entry so historic usage stays replayable.
- New `MODEL.FIREWORKS.INKLING` (`accounts/fireworks/models/inkling`) —
  $1.00/$4.05, 1M context, vision and tools.
- New `MODEL.FIREWORKS.NEMOTRON`
  (`accounts/fireworks/models/nemotron-3-ultra-nvfp4`) — $0.60/$2.40, already
  priced from its earlier stint in the catalog. It was retired 2026-07-21 for
  nondeterministic structured output; `structured` now passes 6 for 6 on
  resample, so it is pinned `ok` on evidence. A regression should pin
  `structured: "warn"` rather than remove the model again.

### Divergences from the other OpenAI-compatible providers

Both verified against the live API on 2026-08-01:

- **Unknown request fields are rejected with HTTP 422 `extra_forbidden`.**
  Mistral has no `user` field, and names the seed `random_seed`. The adapter
  never sends `user`, and `providerOptions` is not a free-form passthrough on
  this provider — values must belong to Mistral's own request schema.
- **The error `message` is polymorphic** — a plain string on model-level
  errors, an object (`{ detail: [{ loc, msg }] }`) on schema validation. The
  client renders the object form as `body.field: message` rather than
  `[object Object]`, preserving the field names that make a 422 actionable.
- Reasoning responses return `content` as an **array of chunks**
  (`thinking` then `text`) rather than a string. The adapter splits them, so
  `content` stays the answer and the thinking text lands on `reasoning`.
- The rate-limit error `type` is `rate_limited`, not the `rate_limit_error`
  named in Mistral's published error glossary.

### Exchange capture from `stream()` (#471)

- `stream()` now settles an exchange envelope on every call, firing
  `onExchange` and honoring `LLM_EXCHANGE_ENABLED` the way `operate()` does.
  Which transport a caller picks no longer decides whether the turn is
  recorded.
- Settlement lives in `StreamLoop` rather than the `Llm` facade: every
  provider's `stream()` delegates to the loop, so a provider-direct caller is
  covered, and a stream has no fallback chain for the facade to resolve. The
  loop stamps `fallbackUsed: false` / `fallbackAttempts: 1` itself.
- It runs from a `finally`, which an abandoned generator closes through, so a
  consumer that stops reading still records what it consumed with
  `status: "incomplete"`. Normal termination settles `completed`; an error
  settles `incomplete` with the error body.
- `historyDelta` carries the streamed assistant text alongside the turn's tool
  calls and results. The text is recorded for the envelope only — the history
  resent to the provider is unchanged.
- A generator has no response object, so `onExchange` and the store are the
  whole surface; there is no `response.exchange` for a stream. `stopReason` and
  `ids` are unset, which the streamed transport does not surface.

### Caller `AbortSignal` (#472)

- `LlmOperateOptions` takes an optional `signal: AbortSignal`, honored by both
  `operate()` and `stream()`. Every adapter already forwarded a signal to its
  provider SDK; only the caller-facing option was missing.
- The loops link the caller's signal into the per-attempt controller they
  already create, so an abort cancels the in-flight provider request instead of
  letting a closed browser tab keep spending tokens.
- A caller abort is terminal and never retried. `operate()` rejects with the
  new `LlmAbortError` (`category: "aborted"`, status 499, exported from the
  package root); `stream()` yields an error chunk carrying the same
  status/title, then its final `done` chunk, so a consumer's `for await` ends
  rather than throwing. An already-aborted signal fails before the first
  request goes out.
- `StreamLoop` aborts its active controller on teardown, so abandoning the
  generator stops the upstream request whether or not a `signal` was passed.
- The exchange envelope still settles on an abort, with `status: "incomplete"`
  and whatever usage and history accumulated.

## Testing

- 93 new unit tests across `MistralAdapter`, `MistralClient`, and
  `MistralProvider`, plus a Mistral block in `determineModelProvider` with
  regression assertions that Bedrock- and OpenRouter-hosted Mistral ids keep
  their existing providers.
- Env-gated live hot tests at
  `src/providers/mistral/__tests__/client.hot.spec.ts`, including an assertion
  that unknown fields still 422 — the adapter depends on that staying true.
- All seven live capability cells (plain, tools, structured, both, pdf, image,
  temperature) pass against the real API for both cataloged chat models, with
  no `MATRIX_EXPECT` override.
- **The live matrix now paces its own requests.** Mistral enforces a
  requests-per-second ceiling that varies by tier and model and returns a bare
  429 with no `Retry-After`, which `operate()` classifies as terminal rather
  than retrying. `test/rateLimit.ts` holds the per-model rates and the matrix
  spaces every model request through the `beforeEachModelRequest` hook, so
  multi-turn cells are paced turn by turn rather than cell by cell. Override
  with `APP_RPS`.
- 9 tests for streamed exchange capture
  (`src/operate/exchange/__tests__/streamExchange.spec.ts`) covering
  completion, usage totals, tool-call history delta, persistence under
  `LLM_EXCHANGE_ENABLED`, an abandoned generator, a thrown stream, and a
  throwing callback.
- 9 tests for cancellation (`src/operate/__tests__/abortSignal.spec.ts`)
  covering both loops: pre-aborted signals, signal linking into the provider
  request, no retry after an abort, teardown abort on an abandoned generator,
  and exchange settlement on abort.
