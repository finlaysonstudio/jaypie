## Changes

- `MetaProvider` (`PROVIDER.META`, name `meta`) calls Meta's Model API at
  `https://api.meta.ai/v1`. The API serves the OpenAI Responses protocol, so
  `MetaAdapter` extends `OpenAiAdapter` the way `XaiAdapter` does and inherits
  request building, tool handling, structured output, streaming, and `input_file`
  data URIs. `Llm` resolves the provider from the model id, the bare name
  `meta`, or a `meta:` prefix.
- `MODEL.MUSE_SPARK` is `muse-spark-1.3` and `PROVIDER.META.DEFAULT`.
  `MODEL.MUSE_SPARK_CONTRIBUTOR` is `muse-spark-1.3-contributor`: the same
  model at roughly a tenth of the price in exchange for data use (prompts and
  completions may train Meta models), limited to 100 RPM. The contributor tier
  is an explicit opt-in and is never the default.
- `COST` prices all five Muse Spark ids: `muse-spark-1.3` and `muse-spark-1.2`
  at $1.25 input / $4.25 output with $0.15 cache reads, the `-contributor` ids
  at $0.10 / $0.20 with $0.002 cache reads, and `muse-spark-1.1` at the
  standard rate. Reasoning bills as output; no write premium is published.
- The API key is read from `META_API_KEY`, then from `MODEL_API_KEY` (the name
  Meta's own docs and SDK examples use), then an explicit `apiKey` option wins
  over both. `ConfigurationError` when none resolves.
- `reasoning.effort` walks Meta's `minimal | low | medium | high | xhigh | max`
  ladder. `max` is limited to the Standard-tier `muse-spark-1.3`, so `highest`
  on the contributor id or an older release clamps to `xhigh` and logs at
  debug. Muse Spark always reasons: `none` is rejected and never emitted.
  `reasoning.summary: "auto"` is requested on every Muse Spark id.
- The `user` option is sent as `safety_identifier`, the field Meta names as the
  successor to the deprecated `user`.
- A 402 from Meta is classified as a terminal billing failure (`LlmQuotaError`,
  `reason: "billing"`) rather than retried.
- `PROVIDER.META.MODEL_MATCH_WORDS` is `["muse"]`. `meta` is deliberately not a
  match word: `meta.llama-*` stays on Bedrock and `meta-llama/*` on OpenRouter.
- `OpenAiAdapter` gains a `protected supportsReasoningSummary(model)` hook so
  OpenAI-compatible subclasses can request reasoning summaries for models
  outside OpenAI's `gpt-5+` / o-series naming.

## Testing

- Unit coverage for the adapter (field renaming, reasoning summary, effort
  ladder and the `max` gate, `prompt_cache_key`, usage with `cached_tokens` and
  `reasoning_tokens`, 402 classification), the provider (key resolution order),
  routing (every cataloged and priced id, the `meta:` prefix, Bedrock and
  OpenRouter ids left alone), and constants (default never the contributor
  tier, every Muse Spark price within the `COST` invariants).
- A `meta` group joins the CI capability matrix in `npm-check.yml` and
  `npm-deploy.yml`, keyed on `CICD_META_API_KEY`.
- Live verification on 2026-09-05: the capability matrix passed on both
  cataloged models. The `pdf` cell on `muse-spark-1.3` overran the 180 second
  cell deadline on the first run and passed on a rerun, so no `MATRIX_EXPECT`
  entry is pinned for it. Live probes confirmed `max` is accepted on
  `muse-spark-1.3` and rejected with a 400 on the contributor tier, the
  response echoes the literal model id, a repeat call reports `cached_tokens`,
  and a two-turn tool call replays the reasoning item without error. Before
  billing was configured every call returned 402 `billing_not_configured`,
  which exercised the billing classification.
- `test/matrix.ts` now exits the process explicitly after a passing run. An
  abandoned cell keeps retrying in the background, and its backoff timers and
  open socket held the event loop open after the verdict printed.
- `test/matrix.ts` treats a provider refusal (`stopReason: "refusal"`) as an
  inconclusive cell, alongside the cell deadline and an exhausted turn budget.
  The `claude-opus-5` pdf cell refused on five of seven CI runs across two
  branches and answered on every local run, so failing on it reported a
  classifier flake as a missing capability. Every cell now requests the
  exchange envelope so the stop reason is observable; the refusal still prints
  in ISSUES.
