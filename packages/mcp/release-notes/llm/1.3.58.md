## Changes

### Empty structured output (issue #608)

`operate` with `format` resolved successfully when the provider returned no content (observed: Gemini, 0 output tokens, `fallbackUsed: false`, no warning). The caller received `content: undefined`.

- Empty content (`undefined`, `null`, or whitespace) on a `format` request settles `status: "incomplete"` with `error.reason: "incomplete"`, `error.detail` `Model returned no content: <stop reason>`, and `stopReason: "other"`. It logs at `warn` with the provider's stop reason.
- Adapters with a corrective turn (Fireworks, Google) try it once before settling empty. Salvage and fresh-context conversion are skipped: there is no text to read.
- A fallback chain moves past an empty response like any cut-off. An earlier partial is kept over a later empty response.
- When only empty responses come back, `operate` throws `LlmIncompleteError` (status 502) whatever `incomplete` says: there is no partial to return.
- Requests without `format` are unchanged.

### Gemini stop reasons

- A blocked prompt returns no candidate; `promptFeedback.blockReason` is now reported as the stop reason, so it fails over and names its cause.
- `OTHER`, `LANGUAGE`, `IMAGE_SAFETY`, and `MALFORMED_FUNCTION_CALL` are incomplete finishes. `IMAGE_SAFETY` normalizes to `content_filter`.

## Testing

- `OperateLoop` specs cover empty and whitespace content with `format`, the corrective turn on empty content, settling empty once turns run out, no conversion of empty content, and unchanged behavior without `format`.
- `Llm` class specs cover failover on empty content, throwing for a lone model and a whole chain, and a partial kept over a later empty response.
- `runWithFallback`, `GoogleAdapter`, and `incompleteReason` specs cover `isEmptyResult`, the block reason, and the new Gemini finishes.
