## Changes

- The stale rejection guard no longer adds one `process` `unhandledRejection` listener per retrying request (#597). All active guards share a single listener, installed with the first guard and removed with the last, so the listener count stays constant under concurrency
- Each guard keeps its own caught errors; the shared listener suppresses a transient network error or a rejection matching any active guard's caught errors
- A redundant `remove()` no longer affects other active guards

## Testing

- `npm run test -w packages/llm`: new specs cover a constant listener count across 12 concurrent guards, redundant `remove()`, and cross-guard sibling suppression
