## Changes

### Union parameter limit (issue #616)

Anthropic rejects native structured output (`output_config.format`) when a schema carries more than 16 union-typed parameters, and every `.nullable()` field is one. The 400 ("Schemas contains too many parameters with union types") matched none of the patterns that trigger the `structured_output` tool fallback, so `operate` failed, and an Anthropic fallback in a chain could not serve such a schema.

- `AnthropicAdapter.buildRequest` counts the schema's union-typed parameters (`anyOf` or a `type` array, at any depth) and sends a schema over 16 straight to the tool path, avoiding the rejected round trip.
- The union-limit 400 is retried through the tool path for the request that received it.
- Neither path demotes the model. The limit belongs to the schema, so the same model keeps native `output_config.format` for smaller schemas.
- Both log at debug.
- Citations and deprecated-field 400s still propagate unchanged.

## Testing

- `AnthropicAdapter.spec.ts` covers the retry, the model staying native afterward, the count at 16 and 17, `type` arrays and nested unions, and the debug log on each path.
- Verified live on `claude-sonnet-5-5` and `claude-opus-5-5`: the API accepts 16 union-typed parameters natively and rejects 17.
