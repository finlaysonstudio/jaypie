## Changes

- New `LlmResponseErrorReason` enum, exported from the package. A response the
  operate or stream loop settled on its own policy budget carries
  `error.reason`: `max_turns` (429) or `tool_errors` (502).
- Both stops build their payload in one place (`src/operate/loopStop.ts`),
  replacing eight hand-written copies across `OperateLoop` and `StreamLoop`
  (in-loop and resume paths).
- The live capability matrix classifies a cell that ended in `max_turns` as
  inconclusive: it reports ⚠️ with its detail in the ISSUES block and is
  excluded from the mismatch count, so it no longer fails the run.

## Motivation

A model that loops tool calls until the turn budget runs out has not shown it
lacks a capability. It has shown that this run did not converge, and the
outcome is nondeterministic: the same `both` cell passed on a PR run and failed
on the merge run twelve minutes later (issue #505), failing the deploy
workflow.

Detecting the case needs a better discriminator than `status === 429`, which a
genuine provider rate limit also carries. `error.reason` is that
discriminator, and it is useful outside the matrix: a caller can retry with a
larger budget instead of reporting a capability failure.

## Migration

- No breaking change. `error.reason` is additive and optional; `status`,
  `title`, and `detail` are unchanged.
