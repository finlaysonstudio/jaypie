## Changes

### New Features

- `Llm.question(state, { questions })` is a fourth entry point, in TypeSafe's
  (Jev's) shape: `noul`, `choice`, and `score` questions asked of a state,
  answered one apiece with probabilities. Static and instance forms mirror
  `operate`, including `model` array sugar, `fallback`, `retry`, `signal`, and
  `user`.
- New provider `typesafe` serves TypeSafe's System One models over
  `POST /v1/systemone`, with match words `jev` and `typesafe` and
  `TYPESAFE_API_KEY`. It implements `question` only: a System One model
  generates no text, so `send` throws `NotImplementedError` and the provider
  offers no `operate` or `stream`. The client is `fetch` against the two
  documented routes; no SDK dependency is taken.
- `MODEL.JEV` is `jev-1.13.0`, the versioned id the API echoes on every
  response. The `jev-latest` and `jev-preview` aliases still route to the
  provider through the match words. `COST["jev-1.13.0"]` is $0.042 input and
  $0 output, which TypeSafe bills for answers.
- Every other provider answers the same call through an emulator: one
  structured `operate()` call at `temperature: 0` and `turns: 1`, asking for
  the full distribution, from which choice (argmax), score
  (probability-weighted level index), and confidence are derived. A chain can
  mix the two, so a rate-limited or unreachable Jev falls through to a
  traditional model without the caller's request or response shape changing.
- The response carries `emulated`. When it is `true`, `probabilities` are
  model-reported (normalized in code) and `confidence` is Jaypie's normalized
  peak probability, `(max(p) - 1/n) / (1 - 1/n)`, exported as
  `peakConfidence` alongside `normalizeDistribution`. TypeSafe has not
  published its own formula; normalized peak reproduces both documented
  examples and a live Jev call within rounding, and is replaced by TypeSafe's
  when it publishes.
- TypeSafe's question limits (1 to 255 choice options, 2 to 10 ordered score
  levels, non-empty instructions, `noul` criteria restricted to `true` and
  `false`) are validated at the entry point for **every** provider, so a
  question that validates is answerable anywhere in a chain. A violation
  throws `BadRequestError` naming the question id.

### Bug Fixes

- The Anthropic hot spec streamed with `max_tokens: 64`. The 5-family models
  open a response with a thinking block, so the budget was spent before any
  text delta arrived and `streams text deltas` failed for Fable 5.1, Opus 5,
  and Sonnet 5. The budget now accommodates the thinking block and the test
  stops reading at the first text delta.
- A per-call `model` no longer follows `operate()` onto a fallback provider.
  `operate(input, { model: ["gpt-5.6-luna", "claude-haiku-4-5"] })` sent the
  primary model id to the fallback, asking Anthropic for an OpenAI model. Each
  fallback now runs the model its own chain entry names.

### Internal

- The primary-then-chain loop moves to `src/util/runWithFallback.ts` and
  serves both `operate` and `question`. Exchange settlement stays in
  `operate`; `question` emits no exchange in this release.
- `MODEL.JEV` is excluded from the live capability matrix: a System One model
  implements neither `operate()` nor `send()`, so every cell would fail by
  construction.

## Testing

- Live, 2026-09-18 (`npm run test:llm:question`): all three question types
  against `jev-1.13.0` natively and against `claude-haiku-4-5` and
  `gpt-5.6-luna` by emulation, plus a chain falling from an unknown Jev model
  to emulation. 4 of 4 passed, with the three models agreeing on every answer
  (choice `billing`; noul 0.97, 0.92, 0.98; score 1.86, 1.60, 1.83 on a 0 to 2
  scale).
- New unit coverage for validation, the emulator (prompt, schema,
  normalization, argmax, weighted score, confidence against TypeSafe's
  documented examples), `Llm.question` fallback behavior, the TypeSafe client's
  status-to-error mapping, and provider routing. A hot spec exercises both
  live routes when `TYPESAFE_API_KEY` is set.
