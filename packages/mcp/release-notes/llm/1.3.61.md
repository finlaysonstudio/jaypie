## Changes

### `modelOptions` (issue #614)

`providerOptions` reached the primary only, so a fallback ran on defaults unless the caller rebuilt the chain with options on every entry.

- `modelOptions` (`LlmModelOptions`) on `operate` and `stream` keys provider options by exact model id, `MODEL` catalog key, provider (or the `gemini` alias), or `default`. Each attempt (primary, fallback, linger pass) resolves it against its own model.
- Every matching key merges, least to most specific: `default` → provider → catalog key → exact id. Objects merge deeply; arrays and scalars replace.
- First-class `effort`, `temperature`, and `format` still win over resolved options.
- When `modelOptions` is set, `providerOptions` (call and chain entry) is ignored.
- `LlmExchangeRequest.providerOptions` records the options each attempt sent.
- `resolveModelOptions({ model, modelOptions, provider? })` returns `{ keys, model, options, provider }`.

### Deprecations

- `providerOptions` on `LlmOperateOptions` and `LlmFallbackConfig` is deprecated and removed in 2.0. Use `modelOptions`.
- `Llm.send` (instance and static) is deprecated and receives no new features. Use `operate`.

## Testing

- `modelOptions.spec.ts` covers merge order, deep merge, array replacement, the provider alias, ignoring `providerOptions`, and the issue's example through the OpenAI and Google adapters.
- `OperateLoop` and `StreamLoop` specs cover resolution and the exchange record; `Llm` specs cover `modelOptions` reaching every fallback and the linger pass.
