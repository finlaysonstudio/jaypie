## Changes

- The Google adapter passes every tool's `parameters` through `jsonSchemaToOpenApi3`, the same conversion `responseSchema` uses. Previously Gemini received the schema verbatim and rejected keywords outside its subset (`additionalProperties`, which `z.toJSONSchema` always emits), failing the request and pushing every call to the fallback provider (#593)
- Covers user tools, the legacy `structured_output` tool, and the Gemini 3 runtime fallback that rebuilds the request after the native `responseJsonSchema` + tools combo is rejected
- `const` and `$ref` are stripped, as in `responseSchema`; literal and referenced constraints do not reach Gemini

## Testing

- `npm run test -w packages/llm`: new GoogleAdapter specs assert no `$schema`, `$defs`, `$ref`, `additionalProperties`, or `const` reaches any function declaration, across nested `properties`, `items`, and `anyOf`, and that caller schemas are not mutated
