## Changes

### Per-model effort (issue #612)

A fallback chain mixes providers whose reasoning cost differs sharply at the same level, but `effort` was one value per call.

- `effort` accepts `LlmEffortMap`. Each attempt (primary, fallback, linger pass) resolves its own level: exact model id, then `MODEL` catalog key whose value is exactly the model, then provider (or the `gemini` alias), then `default`. No match leaves the provider default.
- Catalog keys match exact catalog values only, never name fragments, so `flash` cannot catch both Gemini Flash and GLM Flash.
- `LlmFallbackConfig.effort` sets a single level for one entry and replaces the call's value there.
- `LlmExchangeRequest.effort` records the level each attempt resolved.

### `resolveEffort`

- `resolveEffort({ model, effort, provider? })` returns `{ level, model, native, papered, provider }`, where `native` is the request fragment the adapter sends (e.g. `{ thinkingConfig: { thinkingLevel: "LOW" } }`). Undefined `native` means no level resolved or the model has no reasoning control.
- Adapters expose `resolveEffort` and build requests from it, so the export and the wire request share one mapping.

## Testing

- `resolveEffort.spec.ts` covers map precedence, catalog keys, the provider alias, and native fragments per provider.
- `OperateLoop` and `StreamLoop` specs cover map resolution and the exchange record; `Llm` specs cover per-entry effort on a fallback.
