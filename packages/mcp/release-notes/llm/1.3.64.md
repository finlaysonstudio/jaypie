## Changes

### Models that cannot combine `format` with tools

- `LLM.FORMAT_WITH_TOOLS_UNSUPPORTED` lists, by literal id, the models known not to settle when one call carries both `format` and `tools`: `mistral-large-4`, `mistral-large-4-0`, and `mistral-medium-3-5`. Either option alone works on them.
- `operate()` and `stream()` log a warning when such a model is asked for the pair, then run the call anyway.
- In a fallback chain the attempt throws `LlmUnrecoverableError` before any request goes out, so the next model takes over at once. The linger pass on the primary still runs the call.
- The live matrix skips the `both` cell for every listed id, cataloged or passed through `APP_MODELS`. `APP_FORCE=1` still runs it.

### Mistral Large 4

- `MODEL.MISTRAL.LARGE` is now `mistral-large-4-0` (public preview since 2026-10-06), superseding `mistral-large-2512`. `PROVIDER.MISTRAL.DEFAULT` follows. Mistral's own `mistral-large-latest` alias still names Large 3.
- `COST` prices `mistral-large-4-0` at its list rate: $1.36 input, $4.18 output, and $0.14 cached input per million tokens. Mistral currently bills half that under an open-ended "sale price"; promotional rates are not modeled. The `mistral-large-2512` entry stays so historic usage remains replayable.
- `MistralAdapter` sends `reasoning_effort` to Large 4 and later. Large 4 accepts `none` and `high` like the other reasoning models. Large 3 and `mistral-large-latest` still omit the field.

### Mistral Medium

- `MODEL.MISTRAL.MEDIUM` is back in the catalog as `mistral-medium-3-5`. It was removed on 2026-08-02 because it cannot combine `format` with tools; the marker above now carries that limit.

### Greedy sampling

- `MistralAdapter` sends `top_p: 1` alongside `temperature: 0` unless the caller set `top_p`. Large 4 rejects a bare `temperature: 0` with "top_p must be 1 when using greedy sampling" while it reasons. 1 is the API default, so other models are unaffected.

### Behavior to expect from Large 4

- A call that passes both `format` and `tools` on `MODEL.MISTRAL.LARGE` or the Mistral default now warns, and usually does not finish. It worked on Large 3.
- PDF and other `document_url` input fails with "The model `mistral-ocr-2512` does not exist for router `ocr`". This is on Mistral's side and worked on Large 3. `Llm.ocr` is unaffected.
- Reasoning is on by default and counts toward output tokens. Pass `effort: "lowest"` to turn it off.
- List price is about 2.7 times Large 3's.

## Testing

- `MistralAdapter.spec.ts` covers the effort gate for Large 4 against Large 3, and the `top_p` pin.
- `constants.spec.ts` covers the Mistral catalog, its prices, and the marked ids.
- `guardFormatWithTools.spec.ts` covers the warning, the fail-fast throw, and the silent cases; `Llm.class.spec.ts` covers `failFast` reaching chain attempts and not the linger pass or a lone model.
- Verified live on 2026-10-09: a `format` plus `tools` call on `["mistral-large-4-0", MODEL.MISTRAL.SMALL]` failed over and answered in 1.1 seconds.
- Verified live on 2026-10-09 with `APP_GROUP=mistral`: `mistral-large-4-0` passes five cells with `both` and `pdf` skipped, `mistral-medium-3-5` passes six with `both` skipped, and `mistral-small-2603` passes all seven.
