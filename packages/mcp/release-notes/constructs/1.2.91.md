## Changes

- **`waf.rateLimit`** on `JaypieDistribution` and `JaypieWebDeploymentBucket`
  takes `{ exemptIps, perIp }` (#589). `exemptIps` lists IPv4 and IPv6 CIDRs
  the `RateLimitPerIp` rule neither counts nor blocks. The construct creates
  one `AWS::WAFv2::IPSet` per address family and scopes the rate-based
  statement down to everyone outside them. `rateLimitPerIp` keeps working;
  setting it with `rateLimit.perIp` throws `ConfigurationError`, as does an
  invalid CIDR.
- **`JaypieSsoPermissions` Agent set** no longer grants actions that run code
  under a service execution role (#570): `iam:PassRole`, Lambda invoke, code,
  configuration, version, alias, and event-source-mapping writes, ECS task
  definition, run, start, and service updates, `ecr:PutImage` and layer
  uploads, `states:StartExecution`, `states:StartSyncExecution`, and
  `pipes:StartPipe`.
- The Agent set also drops account-wide `secretsmanager:GetSecretValue`,
  `ssm:PutParameter`, and `s3:PutObject`.
- `AgentDenyPrivilegedPassRole` stays, so a linked policy granting
  `iam:PassRole` still cannot pass the SSO, organization, or CDK roles.

## Upgrade

- Agent sessions that invoke or update Lambdas, run ECS tasks, start Step
  Functions executions, read secrets, write parameters, or put objects now
  receive `AccessDenied`. Restore a specific workload with a customer managed
  policy linked to the Agent set, scoped to that workload's ARNs. Nothing
  denies these actions, so such a grant takes effect.
- Consumers appending a local `DenyAgentExecutionRoleEscalation` statement can
  remove it.
- `rateLimitPerIp` alone synthesizes the same rule as before; no template
  change without `rateLimit`.
