## Changes

- **`JaypieWebDeploymentBucket`** no longer overrides Cache-Control. Each S3
  object's Cache-Control reaches browsers, so fingerprinted assets uploaded
  `immutable` stay cached instead of downloading on every page view.
- **`securityHeaders.cacheControl`** (`string | false`) on `JaypieDistribution`
  and `JaypieWebDeploymentBucket`. A string overrides the origin's header;
  `false` passes it through.
- `JaypieDistribution` keeps its `no-store, no-cache, must-revalidate,
  proxy-revalidate` default (`CDK.SECURITY_HEADERS.CACHE_CONTROL`).

## Upgrade

- Web buckets now honour the Cache-Control set at upload. The web-deploy
  action uploads documents with `max-age=0, must-revalidate`, so pages still
  revalidate. Objects uploaded without Cache-Control fall back to browser
  heuristics; pass `securityHeaders: { cacheControl: "no-store" }` to keep the
  previous behaviour.
