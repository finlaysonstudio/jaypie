## Changes

- `migrationHandler` returns `{ IsComplete: false }` with no `Data` while a migration is pending.
- Completed polls return `{ Data: result, IsComplete: true }`, and omit `Data` when the handler result is not a plain object.
- `RequestType: "Delete"` short-circuits without invoking the migration: `onEvent` returns `PhysicalResourceId`, `isComplete` returns `{ IsComplete: true }`.

## Motivation

The `cr.Provider` framework throws `"Data" is not allowed if "IsComplete" is "False"`
when a pending `isComplete` response carries any `Data` keys. Any migration set needing
more than one invocation therefore failed the custom resource on the first pending poll,
marking the resource `CREATE_FAILED`. The rollback then invoked the same handler for the
`Delete` request, ran the next pending migration, failed the same way, and left the stack
`ROLLBACK_FAILED`.

Scalar and array results were also submitted as `Data`, which CloudFormation rejects
because `Data` must be a map.

## Migration

No changes required. Handlers returning `{ pending: true }` now poll correctly. Handlers
returning a scalar or array no longer expose that value through `Fn::GetAtt`; return a
plain object to keep resource attributes.

Fixes #510.
