## Changes

- The `jaypie:typescript` block turns off core `no-redeclare`.

## Motivation

Core `no-redeclare` does not understand TypeScript function overloads: it
reports every signature after the first as `'name' is already defined`, so an
overloaded declaration could not lint clean without a per-file disable
comment. TypeScript itself rejects a genuine redeclaration, which makes the
core rule redundant in `.ts` files. This matches what
`typescript-eslint`'s own `eslint-recommended` block does.

## Migration

No consumer config changes required. Any
`// eslint-disable-next-line no-redeclare` on an overload signature is now an
unused directive and can be removed.
