## Changes

- **Node 24.22 compatibility**. `LambdaResponseBuffered` and
  `LambdaResponseStreaming` bind `destroy` and `_destroy` as instance
  properties, as they already do for `write`, `end`, and `_final`. Express swaps
  the response prototype to `ServerResponse`, so `autoDestroy` after finish
  reached `OutgoingMessage.prototype.destroy`, which in Node 24.22.0 reads
  internal state (`kChunkedBuffer`) the adapters never initialize and threw
  `TypeError: Cannot read properties of undefined (reading 'length')`.

## Testing

- `src/adapter/__tests__/destroy.spec.ts` swaps each adapter to Express's
  response prototype and asserts `destroy()` and end-triggered auto-destroy
  complete; verified on Node 24.21.0 and 24.22.0.
