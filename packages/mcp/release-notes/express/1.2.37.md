## Changes

- **`rawHeaders`, `rawTrailers`, `trailers` on `LambdaRequest`** (#532).
  `rawHeaders` is the flat `[name, value, ...]` list Node's `IncomingMessage`
  guarantees, repeating a name per value for multi-value headers.
  `@hono/node-server`-based handlers, including `mcpExpressHandler`, now work
  under `createLambdaHandler`.
- **`host` fallback**. When an event carries no `host` header,
  `requestContext.domainName` supplies it.
- **`createLambdaStreamHandler` guards `awslambda`** (#534). Outside the Lambda
  runtime it returns the plain `(event, responseStream, context)` handler rather
  than throwing `ReferenceError` at import. Response header writes are guarded
  the same way.
- **`name` option** labels unhandled error logs in both `createLambdaHandler`
  and `createLambdaStreamHandler`.
- **Explicit status on an empty return** (#539). A controller that calls
  `res.status(code)` and returns nothing responds with that code and an empty
  body, instead of 204 or an "Illegal call to res.end()" warning. Without an
  explicit `res.status()`, an empty return is still 204. `expressStreamHandler`
  flushes headers before the controller runs, so the rule does not apply there.

  ```typescript
  expressHandler(async (req, res) => {
    res.status(202);
  });
  ```

- Tests cover `logBody` and `sensitiveHeaders` on `expressStreamHandler` (#515).
