## Changes

- Redaction now recurses through nested objects and arrays, so `log.var({ event })` scrubs `event.headers.authorization` and deeper (previously only top-level keys were inspected)
- Expanded name denylist with per-entry renders: credentials render `sk_<last4>`/`md5_<last4>`; `accountNumber`, `routingNumber`, `iban`, `ssn`, `taxId` render last four (`…6789`); card numbers render BIN plus last four (`411111…1111`); `cvv`, `pin`, `otp`, `securityCode` render the literal `redacted` with no partial reveal
- Names match ignoring case and separators (`routing_number` ≡ `routingNumber`)
- Strings matching known credential shapes (`sk_…`, `AKIA…`, `ghp_…`, JWTs) redact under any field name; ambiguous names (`key`, `token`, `auth`, `credential`) redact only when the value looks like a credential, so S3 keys, UUIDs, and paths pass through
- New `secret(value)` marks a value sensitive at creation; logs render it redacted while `JSON.stringify` still yields the true value. `isSecret` and `looksSecret` exported alongside
- Pluggable: `redactKeys` option or `LOG_REDACT_KEYS` env adds denylist names; `redact(value, { key, path })` hook runs ahead of built-in rules; `redact: false` or `LOG_REDACT=false` disables scrubbing. `log.config()` updates at runtime and propagates to derived loggers
