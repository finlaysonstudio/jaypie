## Changes

- `createLayeredStore().find` checks every layer for an exact alias before it
  tries plural/singular fallback in any layer. With `studio:test` and
  `jaypie:tests`, `find("tests")` returns `jaypie:tests` in place of
  `studio:test`, so a local skill cannot shadow an existing Jaypie skill under
  a different spelling (#558).
- `createSkillService` resolves through `find`, so `skill("tests")` follows the
  same order. Namespace-qualified aliases still search only their own layer.
- `createDynamoDbStore({ category })` from the new `@jaypie/tildeskill/dynamodb`
  subpath serves skills from `@jaypie/dynamodb` as `skill` entities with
  deterministic ids (`uuidv5("<category>:<alias>", SKILL_NAMESPACE)`) and
  `metadata.hash`. `@jaypie/dynamodb` is an optional peer dependency that the
  main entry never imports (#557).
- `syncSkills({ from, to })` puts added and changed records, leaves unchanged
  records alone, deletes records missing from `from`, and returns
  `{ added, removed, unchanged, updated }` (#557).
- `SkillStore` gains `delete(alias)`. Memory removes the record, markdown
  removes the file, layered requires a namespace-qualified alias, and DynamoDB
  soft deletes (#557).
- New main exports: `hashSkill`, `registerSkillModel`, `SKILL_MODEL`,
  `SKILL_MODEL_NAME`, `syncSkills`, and the `DynamoDbStoreOptions`,
  `SyncSkillsOptions`, and `SyncSkillsResult` types.
- `createSkillService` throws `BadRequestError` for an invalid alias and
  `NotFoundError` for a missing skill in place of a vanilla `Error`. Messages
  are unchanged.
