## Changes

- Error constructors accept `cause` in the options argument and it reaches
  `error.cause` unchanged. A caught error can now be chained onto the Jaypie
  error thrown in its place, so ESLint's `preserve-caught-error` rule is
  satisfiable and classification that walks a cause chain sees through a Jaypie
  wrapper.
- The base `JaypieError` takes `cause` alongside `status` and `title`. The
  named classes take `cause` only, because status and title identify the class.
- `cause` is assigned only when the option is present, matching native `Error`,
  where an error built without it has no `cause` property.
- `JaypieError` declares `cause` on both the class and the interface, so
  consumers targeting a lib older than ES2022 read it without a structural
  cast. `CauseOptions` and `ErrorOptions` are exported.

Additive and backward compatible. Resolves issue #492.
