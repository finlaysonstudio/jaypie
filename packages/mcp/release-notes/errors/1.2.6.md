## Changes

- Every error class matches with `instanceof` regardless of which export
  condition the comparison came from. The package publishes an ESM build and a
  CommonJS build, each of which owned its own class object, so an error raised
  inside a CommonJS package never matched `instanceof NotFoundError` in an ESM
  package. The failure was silent: the branch simply did not fire.
- `JaypieError` and the generated classes define `static [Symbol.hasInstance]`,
  matching on the structural markers (`isJaypieError` plus `_type`) rather than
  prototype identity. This also holds when two copies of `@jaypie/errors` are
  installed, which collapsing the export conditions would not.
- A subclass of a Jaypie error keeps ordinary prototype semantics, so callers
  can still distinguish their own error from the class it extends.
- Class identity across formats is unchanged: `require("@jaypie/errors")
  .BadRequestError === BadRequestError` remains `false`. Compare with
  `instanceof`, not `===`.

- Add `vite.config.ts` so `npm test -w packages/errors` resolves against the
  package rather than the root `projects` glob.

`jaypie`, `@jaypie/aws`, `@jaypie/core`, `@jaypie/datadog`, `@jaypie/express`,
`@jaypie/kit`, and `@jaypie/lambda` re-export these classes and inherit the fix.

Additive and backward compatible. Resolves issue #502.
