## Changes

- `storeExchange` carries a parked envelope's `pending` block (issue #473 in
  `@jaypie/llm`: outstanding external tool calls, re-entrant history, turn
  count) into the persisted entity's `state.pending`. A parked exchange
  persists at status `in_progress`, already in the registered vocabulary.
- The 400KB item-limit truncation order protects the resume payload: `pending`
  survives `historyDelta`, `input`, and `content`, and is dropped only as a
  last resort so the record itself still writes. A truncated resume payload is
  useless; a lost record is worse.
